# Phase 6.2.16 — Thai Meaning Remediation Pipeline Before Mass Human Review

## Executive Summary & Authoritative Readiness Baseline

Phase 6.2.16 establishes a safe, reversible, dataset-wide remediation pipeline targeting the upstream content quality of Thai definitions (`meaning_th`) across the 10,000 staged vocabulary units. In Phase 6.2.15, empirical audit identified that 8,318 staged records contained synthetic template prefixes, canned boilerplate phrases, or PoS structural mismatches generated by earlier heuristic drafts.

This phase implements a deterministic multi-tier remediation engine that safely archives all detected synthetic drafts into `provenance.previous_drafts`, replaces them with clean, PoS-aligned, topic-informed Thai candidate definitions, and enforces a zero-tolerance structural quality gate.

## Content-Status Taxonomy & Classification

To ensure operational clarity across human reviewers, devops engineers, and product leadership, all content in the Glova pipeline is categorized under five distinct statuses:

| Status Category | Machine Identifier | Description & Authority | Learner-Ready? |
| :--- | :--- | :--- | :--- |
| **1. Source-Verified** | `SOURCE_VERIFIED` | Originates directly from an authoritative licensed corpus (OEWN synset definition, CMUdict Arpabet transcription) with confirmed alignment. | No (requires complete human QA package) |
| **2. AI-Generated Draft** | `AI_DRAFT` | Machine-generated or heuristically derived candidate meaning. Strictly uncertified; subject to human review. | No |
| **3. Deterministic QA Gate Pass** | `qa_dimensions.*: PASS` | Passes all structural format and linguistic quality checks (no synthetic templates, length bounds, PoS alignment). | No (format valid, human judgment still pending) |
| **4. Human-Approved** | `APPROVED` | Individually evaluated, edited if necessary, and approved by an authorized human lexicographer. Recorded in review ledger. | **Yes** (qualifies toward learner-ready pool) |
| **5. Learner-Ready** | `is_active: true` | Fully verified, human-approved, and promoted to production database for learner consumption. | **Yes** |

## Detection & Quality Gate Architecture

The deterministic detector `detectBadThaiMeaning(meaningTh, partOfSpeech)` evaluates Thai definitions against four failure criteria:

1. **Synthetic Template Prefixes**: Detects 14 canned domain prefixes, including:
   - `สิ่งประดิษฐ์ อุปกรณ์ หรือโครงสร้างที่ใช้สำหรับ`
   - `การปฏิบัติหรือทำให้เกิดผลลัพธ์`
   - `ความหมายในบริบทผู้เรียน`
   - `อย่างมีลักษณะที่แสดงถึง หรือในทิศทางที่`
   - `สภาวะ คุณลักษณะ หรือความรู้สึก`
   - `บุคคลหรือผู้ปฏิบัติหน้าที่เกี่ยวข้องกับ`
   - `การแสดงออกหรือการสื่อสาร`
   - `อาหาร การปรุงอาหาร และโภชนาการ`
2. **Canned Boilerplate Phrases**: Flags generic filler endings such as:
   - `ตามนิยามเฉพาะของความหมายนี้`
   - `สิ่งของ แนวคิด หรือสภาวะตามนิยามของความหมายนี้`
   - `คำนามหมายถึงสิ่งของ แนวคิด หรือสภาวะ`
   - `คำกริยาหมายถึงการกระทำ`
3. **Unparenthesized Latin Script**: Flags any English or Latin word tokens $\ge 3$ characters that appear outside parentheses.
4. **PoS Structural Mismatch**: Rejects verbs that define nominal entities (`สิ่งของ...`, `อุปกรณ์...`, `บุคคล...`).

## Multi-Tier Candidate Generation Pipeline

When a unit's Thai meaning is flagged as synthetic, the remediation engine generates replacement candidates according to a strict priority hierarchy:

```
[Candidate Request]
        │
        ▼
[Priority A: Licensed Bilingual Sources]
  (Checked against licensed lexical data)
        │ (If not matched)
        ▼
[Priority B: Curated Glova Lexical Registry]
  (Checked against high-frequency headwords & polysemous sense overrides)
        │ (If not matched)
        ▼
[Priority C: Contextual Sense Drafter v2]
  (PoS-aligned, topic-informed pure Thai domain generator)
        │
        ▼
[Structural Quality Gate Validation]
  (validateThaiMeaningQuality)
        │
        ▼
[Archive Original Draft in provenance.previous_drafts]
        │
        ▼
[Apply Candidate as AI_DRAFT (lifecycle_status = REVIEW_REQUIRED)]
```

### Reversible Archiving Format

Before any field modification occurs, the engine archives the original draft into `provenance.previous_drafts`:

```json
{
  "field": "meaning_th",
  "value": "อย่างมีลักษณะที่แสดงถึง หรือในทิศทางที่กาลเวลา ช่วงเวลา และลำดับเหตุการณ์ ตามนิยามเฉพาะของความหมายนี้",
  "source": "glova_offline_thai_sense_drafter_v1",
  "review_status": "AI_DRAFT",
  "archived_at": "2026-09-26T14:31:49.063Z",
  "reason": "DETECTED_SYNTHETIC_TEMPLATE",
  "detection_reasons": [
    "Contains banned synthetic domain template prefix: \"อย่างมีลักษณะที่แสดงถึง หรือในทิศทางที่\"",
    "Contains banned synthetic boilerplate phrase: \"ตามนิยามเฉพาะของความหมายนี้\""
  ]
}
```

## Preservation of Non-Target Fields & Safety Invariants

1. **Example Sentences Untouched**: In strict compliance with the Phase 6.2.16 mandate, `example_sentence` was not modified during remediation. Addressing example sentence quality (fragments, terminal punctuation, Mad-Lib boilerplate) is reserved for dedicated downstream phases.

3. **Database Isolation**: Zero writes or mutations to the production Supabase database occurred.
